# MONTAS · Организатор

Отдельный прототип кабинета организатора, каталога и страниц мероприятий. Адрес опубликованной версии: https://supervasek38.github.io/organizer/.

В репозитории теперь есть собственные исходники Flutter в `app/`. Развитие этого кабинета независимо от основного MONTAS. Пользовательский кабинет здоровья, кабинет специалиста и остальные рабочие области сюда не подключены. Старый экспорт из основного проекта больше не нужен: он перезапишет отдельную сборку и потеряет её новые возможности.

## Структура и локальный запуск

- `app/` — исходники, ресурсы и тесты самостоятельного приложения.
- `site/` — готовая web-сборка для локального просмотра.
- `scripts/build.ps1` — собирает `app/` и заменяет `site/` только после успешной сборки.
- `serve.py` — отдельный сервер на порту 8081 без кеширования; основной прототип на 8080 не затрагивается.
- `!additional/` — локальные материалы, исключены из Git.

Flutter 3.47.7, Python 3. Выполнить из корня этого репозитория:

```powershell
.\scripts\build.ps1
python .\serve.py
```

Открыть http://127.0.0.1:8081/organizer/. Если Flutter не в PATH, передать `-Flutter 'полный\путь\к\flutter.bat'`. Для просмотра уже готовой сборки достаточно второй команды.

Проверка исходников из `app/`:

```powershell
flutter pub get --enforce-lockfile
flutter analyze --no-pub lib test
flutter test --no-pub
```

Новый дизайн применяется только к этой странице отдельного приложения: фирменный знак, палитра, ближайшее событие, подготовка, показатели и список мероприятий. Существующие переходы сохранены; на узких экранах используется нижняя навигация. Источники и решения описаны в `DESIGN-TODAY.md`.

## Партнёрства: первый этап

Концепция основана на локальной презентации MONTAS_PARTNERS_CRM_concept.pptx. Внешнему организатору доступны его заявки и предложения; внутренняя CRM сотрудников MONTAS не реализована.

1. «Партнёрства» в меню → «Нужны партнёры» → выбрать опубликованное событие. Также есть кнопка в карточке события и вкладка в «Управлении событием».
2. Заполнить запрос: категории брендов, формат партнёрства, аудитория, ожидаемые гости, срок подбора, контакт, один пакет с составом и стоимостью. «Заполнить примером» помогает пройти демонстрацию.
3. Сохранить черновик, проверить данные и отправить заявку. Неполный черновик сохраняется, отправка требует заполнения обязательных полей.
4. «Демо: получить два предложения» создаёт варианты VitaLab и MoveWell. Это вымышленные предложения, а не работа реального подбора.
5. Запросить уточнение и получить демо-ответ, отклонить предложение с причиной либо согласовать одного партнёра. Один запрос соответствует одному партнёрскому месту.
6. Увидеть историю и уведомления. Запрос можно отозвать; отмена события закрывает связанные запросы. Изменение опубликованного события требует проверки новых данных перед согласованием.

Проверки покрывают дубликаты запросов, обязательные поля, устаревшие данные, согласование одного предложения, отмену и отзыв, уведомления, полный сценарий на desktop/mobile и связь с мероприятием.

## Мероприятия и каталог

В шапке переключаются «Кабинет организатора» и «Каталог мероприятий». Они используют общие данные текущей вкладки:

- Создание, публикация, редактирование и отмена события.
- Управление событием: обзор, страница события, билеты, участники, материалы, уведомления, статистика и партнёрства.
- До шести форматов участия с вместимостью и демонстрационной ценой.
- Поиск участников, фильтры регистраций и отмен, статистика заполненности.
- Поиск и фильтры каталога, сохранённые события, детальная страница и демо-регистрация. Записавшийся пользователь сразу появляется у организатора.

## Публикация

В GitHub Settings → Pages → Source выбрать **GitHub Actions**. После коммита и push изменений запустить Actions → **Deploy Organizer to GitHub Pages** → Run workflow → main.

Workflow запускается вручную: устанавливает Flutter, проверяет и собирает именно `app/`, затем публикует `app/build/web`. Push сам по себе не публикует сайт. Изменения основного репозитория `montas` на этот сайт не влияют.

## Ограничения демо

События, участники, бренды и суммы тестовые. Календарь примеров привязан к 20 октября 2026 года. Данные, загруженные материалы, заявки и уведомления живут в памяти текущей вкладки; перезагрузка сбрасывает изменения. Реальных рассылок, оплаты, договоров, CRM, серверной авторизации и синхронизации с основным MONTAS нет. Посещение, выплаты, промоутеры и схемы залов не добавляются.
